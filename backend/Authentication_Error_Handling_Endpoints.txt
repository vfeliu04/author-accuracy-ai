Authentication & Error Handling
===============================

Overview
--------
All API endpoints under `/api/*` now enforce a simple API-key based authentication layer and return structured JSON errors. This file captures the design for reference.

Authentication Flow
-------------------
1. `API_KEY` is read from the environment (see `.env.example`).
2. Clients must send the key via the `X-API-Key` header on every request.
3. A decorator (`require_api_key`) wraps sensitive routes (ingest, verify, credibility, claims, chat). If the provided key is missing or mismatched, the endpoint responds with `401` and `{ "error": "Unauthorized" }`.
4. `/health` remains open for uptime checks.

Error Handling
--------------
- `FileNotFoundError` → `404` with the missing path message.
- `ValueError` → `400` with the validation message (e.g., malformed payloads).
- `HTTPException` instances reuse their status code and message but are returned as JSON.
- Any other exception becomes a `500` with `{ "error": "Internal Server Error" }`. Errors are also logged via the shared logger for diagnostics.

Usage Notes
-----------
- Missing or invalid payload fields should raise `ValueError` to ensure a deterministic `400` response.
- Long-running jobs should surface progress via task IDs; the auth/error scaffolding already supports future background execution.
