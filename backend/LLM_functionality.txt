LLM Assistant Functionality
===========================

This document matches the current `ChatService` implementation in `backend/author_ai/pipelines/chat.py`.


Goals
-----
1. Ground every answer in completed pipeline outputs (claims, evidence, validity, credibility).
2. Scope context to the latest completed job or a user-provided job ID.
3. Provide three conversational modes:
   - `evidence` (strict, factual),
   - `guidance` (diagnostics, improvement advice),
   - `creative` (brainstorming clearly labeled as advisory).


Data sources
------------
- **Claims:** pulled from SQLite via `repo.list_claims_by_report(report_id)`. Includes verdict, confidence, explanation, and metadata.
- **Evidence snippets:** grouped per claim using `repo.list_evidence_for_claims`, so we can cite which sources supported a claim.
- **Vector stores:** per-report FAISS indexes (claims + supporting snippets) allow LangChain-style retrieval when needed.
- **Validity / Credibility:** fetched from `repo.get_validity`, `repo.source_usage`, and job result JSON (for recommended sources + overall credibility).
- **Chat history:** stored in `chat_logs`, trimmed to `CHAT_HISTORY_LENGTH` entries.


Request handling
----------------
1. **Routing:** `/api/chat` enforces a completed job. `ChatService.respond` cleans the question, determines intent (general small talk vs. report discussion), and decides whether to suggest a different mode.
2. **Claim context selection:**
   - Embed the question with `embed_texts`.
   - Query the per-report claim index via `VectorStore(report_id, claim_vector_path).search`.
   - Keep up to `CLAIM_CONTEXT_LIMIT` results that exceed `CLAIM_RELEVANCE_MIN`.
3. **Evidence context selection:**
   - For selected claim IDs, group evidence rows and attach uploaded source metadata.
   - Build supporting snippets either directly from the evidence or by querying the per-report source index (same vector store helper) with `SOURCE_CONTEXT_LIMIT`.
4. **Metrics/context blocks:** assemble strings summarizing validity diagnostics (missing topics, methodology gaps), credibility breakdown, and recommended sources (if available).
5. **LLM prompt:** when an OpenAI API key is configured, call `chat.completions.create` with:
   - System prompt tuned per mode (e.g., Evidence mode forbids speculation).
   - User prompt containing: report summary, claim findings, supporting context, diagnostics, chat history stub (if any), and the actual question.
   - Temperature 0.2 for evidence mode, 0.35 for other modes.
6. **Fallback:** without an API key (or when the LLM call fails), `_compose_answer` produces a deterministic answer that lists the claims considered, supporting snippets, metrics, and mode note.
7. **Response payload:** the JSON includes:
   - `answer` text,
   - `claims_used` (id, text, verdict),
   - `sources_used` (source id + snippet),
   - `mode` and optional `suggested_mode`.
   Chat history is persisted via `repo.record_chat_turn`.


Safety & usability
------------------
- No claim data → respond with “No completed report” (HTTP 400).
- If the latest job isn’t DONE, chat rejects the request.
- Mode suggestions: if content implies guidance/creative is better but the user isn’t locked, `suggested_mode` prompts the UI to show a toggle.
- The assistant never fabricates verdicts; claims without SUPPORT context remain labelled as NOT_FOUND.
