Credibility Scoring Pipeline
============================

This reflects the current `CredibilityPipeline` in `backend/author_ai/pipelines/credibility.py`.


Inputs
------
- SOURCE uploads already stored in SQLite (`uploads` table).
- Metadata extracted via `author_ai.services.metadata_enrichment.METADATA`, which inspects the PDF and any cached lookups to return title, authors, publisher, publication date, DOI, confidence flag, and optional `user_adjustment`.


Scoring
-------
For each source PDF:
1. Collect metadata (`metadata = METADATA.collect_metadata(path)`).
2. Compute component scores:
   - **Metadata completeness (0–30):**
     ```math
     30 \times \frac{\text{fields present in } \{title,authors,publication\_date,publisher,doi\}}{5}
     ```
   - **Authority (0–30):** if publisher contains `fao|un|world bank|imf` → 30; any other publisher → 20; otherwise 10.
   - **Recency (0–20):** derive publication year from the date. Age ≤2y → 20, ≤5y → 12, ≤10y → 6, else 3.
   - **Confidence (0–10):** map metadata confidence flag (HIGH 10, MEDIUM 7, LOW 3).
   - **User adjustment (float):** optional metadata-supplied boost/penalty (default 0).
3. Total score = `min(100, sum(components))`.
4. Persist into SQLite (`credibility_scores` table) and update the document metadata with a textual summary plus author/publisher info.


Report-level aggregation
------------------------
- `aggregate_report(report_id)` reads `repo.source_usage(report_id)` (counts how many claims cite each source).
- Weighted average:
  ```math
  \text{overall} = \frac{\sum_i (\text{usage}_i \times \text{score}_i)}{\sum_i \text{usage}_i}
  ```
- Returns `{"report_id","overall","details":[{source_id,usage,score}]}` for storage in the pipeline job result; the dashboard uses this to show top sources and diagnostics.


Configuration
-------------
- All thresholds live in `Settings`: `CRED_TITLE_MATCH_THRESHOLD`, `CRED_RECENCY_DECAY_YEARS`, etc., though the current implementation only uses the recency window and keyword heuristics.
- Metadata enrichment can be extended centrally (e.g., to call Crossref) without touching the scoring logic.
