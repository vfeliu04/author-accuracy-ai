Validity Assessment Pipeline
============================

Based on `backend/author_ai/pipelines/validity.py`.


Inputs
------
- REPORT PDF processed by `IngestionPipeline` (same flow as accuracy: OCR if needed, PyPDF2 text, section metadata, tables).
- `sections` + `body_text` from ingestion.
- Config options (`VALIDITY_TOPIC_THRESHOLD`, `VALIDITY_WEIGHTS`, etc.).


Scoring steps
-------------
1. **Coverage score (0–100):**
   - Look for topic keywords `{climate, supply, logistics, nutrition, conflict}` in the report body.
   - Covered topics = count of keywords present.
   - Missing topics list is persisted for diagnostics.
   - Score formula:
     ```math
     \text{coverage} = 60 + 40 \times \frac{\text{covered}}{5}
     ```
2. **Internal consistency (0–100):**
   - Regex scan sections for `(phrase, number)` pairs.
   - If <2 numeric statements → score 90.
   - Otherwise penalise contradictory numbers referencing the same phrase: `penalty = min(60, contradictions * 10)`, then score = `max(40, 100 - penalty)`.
3. **Methodology score (0–100):**
   - Keywords `{data, sample, method, limitation}` searched per section.
   - Score = `50 + 12.5 * hits`; flags indicate which elements were found for diagnostics.
4. **Context alignment (0–100):**
   - Count occurrences of `{global, africa, asia, europe, america}`.
   - Score = `60 + min(40, 8 * hits)`.
5. **Recency score:** constant 80.0 (placeholder until a richer timeliness model is added).


Aggregation
-----------
- Default weights:
  - coverage 0.25
  - consistency 0.25
  - methodology 0.20
  - context 0.20
  - recency 0.10
- Overall:
  ```math
  \text{overall} = 0.25\,c_\text{cov} + 0.25\,c_\text{cons} + 0.20\,c_\text{meth} + 0.20\,c_\text{ctx} + 0.10\,c_\text{rec}
  ```
- Diagnostics persisted:
  - `sections` count,
  - `average_section_length`,
  - `missing_topics`,
  - `methodology_elements` flags.


Usage
-----
- Scores + diagnostics stored via `repo.upsert_validity`.
- Report metadata receives a textual summary (`validity_summary`, `validity_missing_topics`, `validity_methodology_gaps`).
- `/api/run_pipeline` and `/api/verify/report` return the `ValidityScores` dataclass (converted to dict) so the frontend and chat service have consistent access to the metrics.
